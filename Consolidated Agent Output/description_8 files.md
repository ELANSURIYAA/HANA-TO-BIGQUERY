## Consolidation Logic Flow

### Step 1: Financial Data Foundation (CV_BASE_FIN_WEEKLY_BUDGET_S4)

The consolidation begins with the financial data layer, which combines frozen and live cube data:

1. **Frozen_Cube CTE**: Reads from AZSRP_DS052_VT_S4 with FLAG='FC'
2. **Live_Cube CTE**: Reads from AZSRP_DS041_VT_S4 with FLAG='LC'
3. **Union_1 CTE**: UNION ALL of frozen and live cubes
4. **Aggregated_Budget CTE**: Aggregates amounts by all dimensions
5. **CV_BASE_FIN_WEEKLY_BUDGET_S4_EXPANDED CTE**: Calculates restricted measures and final amount using CASE logic

### Step 2: Filter to Weekly Snapshot (WEEKLY_SNAPSHOT_DS05)

Applies business filters:
- FISCVARNT = 'K4'
- _BIC_ZIO_SWEEK BETWEEN @IP_WEEK_ENDING_FROM AND @IP_WEEK_ENDING_TO
- _BIC_ZIO_VER = @IP_VERSION
- _BIC_ZIO_SAUDT IN ('1', '10')

### Step 3: HR Hierarchy Filtering (HIER_NODE)

1. **CV_BASE_MD_HRRP_NODE_S4_EXPANDED CTE**: Reads HRRP_NODE table
2. **HIER_NODE CTE**: Filters for CORE_RET nodes with HRYVALTO = '99991231'
3. **Join_1**: INNER JOIN with financial data on profit center

### Step 4: Store Attributes Enrichment (STORE_ATTR_ACTUAL)

1. **CV_COMP_MD_SRPACT_STATIC_EXPANDED CTE**: Aggregates store attributes from TBL_WSS_SRP_ATTR_ACT
2. **STORE_ATTR_ACTUAL CTE**: Projects relevant store attributes
3. **Join_2**: LEFT JOIN with financial data on PRCTR

### Step 5: Week Number Calculation (WEEK_NUMBER)

Adds calculated column:
- CAL_STORE_WEEK_NUMBER = RIGHT(CAST(_BIC_ZIO_SWEEK AS STRING), 2)

### Step 6: Comparison Flags Enrichment (COMP_FLAG_BUDGET)

1. **CV_COMP_MD_COMPFL_STATIC_EXPANDED CTE**: Reads TBL_WSS_SRP_COMPFLAG
2. **COMP_FLAG_BUDGET CTE**: Filters by COMP_VER = @IP_VERSION
3. **Join_3**: LEFT JOIN on PRCTR and ZWEEK

### Step 7: Calendar Week Enrichment (CAL_WEEK)

1. **CV_BASE_MD_RCALWEEK_S4_EXPANDED CTE**: Reads ZTFIGL_RCALWEEK
2. **CAL_WEEK CTE**: Projects week dates
3. **Join_4**: LEFT JOIN on ZZWEEK

### Step 8: Profit Center Text Enrichment (PROFIT_CENTER_TEXT)

1. **CV_BASE_MD_CEPCT_S4_EXPANDED CTE**: Reads CEPCT table
2. **PROFIT_CENTER_TEXT CTE**: Projects LTEXT as PROFIT_CENTER_TEXT
3. **Join_5**: LEFT JOIN on PRCTR

### Step 9: Final Calculations and Projections (FLAGS)

Applies final business logic:
- Negates _B631_S_AMOUNT for display (_B631_S_AMOUNT_NEGATIVE)
- Calculates CAL_FS_RX_FLAG based on _BIC_ZWWPC_PA1 prefix
- Calculates CAL_COMP_FLAG based on FS/RX flag and comparison flags
- Calculates CAL_WEEK_NUMBER
- Reverses negation for final _B631_S_AMOUNT

### Step 10: Final SELECT

Projects all columns from FLAGS CTE.

## Business Logic Preserved

### 1. Frozen vs Live Cube Logic
- When @IP_FC_COUNT != '0': Use frozen cube (AZSRP_DS052_VT_S4)
- When @IP_FC_COUNT = '0': Use live cube (AZSRP_DS041_VT_S4)
- Final amount prioritizes frozen cube amount if available, otherwise uses live cube

### 2. HR Hierarchy Filtering
- Only includes profit centers under CORE_RET parent nodes
- Uses current hierarchy (HRYVALTO = '99991231')

### 3. Comparison Flag Logic
- Determines FS vs RX based on first 2 characters of _BIC_ZWWPC_PA1
- Applies corresponding comparison flag (FS_COMP_WK or RX_COMP_WK)
- Defaults to '0' if comparison flag is NULL

### 4. Amount Negation
- Amounts are negated for display purposes (_B631_S_AMOUNT_NEGATIVE)
- Final _B631_S_AMOUNT is calculated as (_B631_S_AMOUNT * -1) * -1 = _B631_S_AMOUNT

### 5. Client Filtering
- Multiple views filter for MANDT/RCLNT IN (120, 200) or ('110', '200')
- Ensures data consistency across client systems

3. **LEFT JOIN**: Comparison flags (preserves records without comparison data)
4. **LEFT JOIN**: Calendar week (preserves records without calendar mapping)
