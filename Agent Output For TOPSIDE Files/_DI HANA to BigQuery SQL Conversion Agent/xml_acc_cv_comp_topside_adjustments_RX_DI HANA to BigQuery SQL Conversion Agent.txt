SOURCE_LOGIC:
This is a SAP HANA Calculation View XML artifact. The root Calculation:scenario has:
- dataCategory="CUBE"
- outputViewType="Aggregation"

Therefore the final output is aggregated and requires GROUP BY on every non-measure output column and aggregation on every measure.

The view logic is:
1. Read topline/topside adjustment facts from CV_BASE_TOPSIDE_ADJUSTMENTS_CAR.
2. Filter facts by WEEK_YEAR between IP_WEEK_ENDING_FROM and IP_WEEK_ENDING_TO.
3. Left join store master attributes from CV_BASE_MD_SRPACT_S4 on PRCTR.
4. Read comp flag data from CV_BASE_MD_COMPFL_S4 and filter it by COMP_VER = IP_VERSION_COMP_FLAG.
5. Left join comp flag data on PRCTR and WEEK_YEAR = ZWEEK.
6. Left join retail calendar week data from CV_BASE_MD_RCALWEEK_S4 on WEEK_YEAR = ZZWEEK.
7. Left join profit center text from CV_BASE_MD_CEPCT_S4 on PRCTR.
8. Compute:
   - CAL_COMP_FLAG as scalar max between FS_COMP_WK and RX_COMP_WK
   - CAL_WEEK_NUMBER as rightmost 2 characters of WEEK_YEAR
9. Expose attributes and measures defined in the logical model.
10. Because the artifact is a CUBE/Aggregation view:
   - base measures must be aggregated with SUM
   - calculated measures must be computed after aggregation, not row-by-row before aggregation

CONVERSION_NOTES:
- The source is a Calculation View XML, so the conversion was derived semantically from nodes, mappings, joins, filters, calculated attributes, and logical model metadata.
- Because the root scenario has dataCategory="CUBE" and outputViewType="Aggregation", final BigQuery SQL includes:
  - GROUP BY for all non-measure output columns
  - SUM aggregation for all base measures
