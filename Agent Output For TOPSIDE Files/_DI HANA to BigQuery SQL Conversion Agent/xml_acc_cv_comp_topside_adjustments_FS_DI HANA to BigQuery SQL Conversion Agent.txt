SOURCE_LOGIC:
This is a SAP HANA Calculation View XML for artifact CV_COMP_TOPSIDE_ADJUSTMENTS. The root element specifies:
- dataCategory="CUBE"
- outputViewType="Aggregation"

Therefore the final output is aggregated output and requires GROUP BY for all non-measure output columns and SUM aggregation for all measures.

The logic is:
1. Read topside adjustment data from CV_BASE_TOPSIDE_ADJUSTMENTS_CAR.
2. Apply a WEEK_YEAR range filter using input parameters IP_WEEK_ENDING_FROM and IP_WEEK_ENDING_TO.
3. Left join store master attributes from CV_BASE_MD_SRPACT_S4 by PRCTR.
4. Read comp flag data from CV_BASE_MD_COMPFL_S4 filtered by COMP_VER = IP_VERSION_COMP_FLAG.
5. Left join comp flag data by PRCTR and WEEK_YEAR = ZWEEK.
6. Left join retail calendar data from CV_BASE_MD_RCALWEEK_S4 by WEEK_YEAR = ZZWEEK to get week start/end dates.
7. Left join profit center text from CV_BASE_MD_CEPCT_S4 by PRCTR to get PROFIT_CENTER_DESCR.
8. Derive:
   - CAL_COMP_FLAG from scalar MAX(FS_COMP_WK, RX_COMP_WK), which should map to BigQuery GREATEST with semantic validation for NULL behavior.
   - CAL_WEEK_NUMBER from rightmost 2 characters of WEEK_YEAR.
9. Expose logical model attributes and measures.
10. Because this is a CUBE/Aggregation output, aggregate all base measures with SUM and aggregate calculated measures after aggregation, grouped by every non-measure output attribute.

CONVERSION_NOTES:
- The source artifact is a HANA Calculation View XML, so the conversion was derived semantically from calculationView nodes, joins, mappings, filters, calculated attributes, logical model attributes, and measures.
- Because dataCategory="CUBE" and outputViewType="Aggregation", the final SQL includes:
  - GROUP BY for every non-measure logical output column
  - SUM aggregation for every base measure
  - Calculated measures applied after aggregation, per instruction
- HANA scalar `MAX(FS_COMP_WK, RX_COMP_WK)` was converted to BigQuery `GREATEST(FS_COMP_WK, RX_COMP_WK)` because this is scalar, not aggregate, semantics.
- HANA `RIGHTSTR(WEEK_YEAR,2)` was converted to BigQuery `RIGHT(WEEK_YEAR, 2)`.
- HANA `IF(...)` was converted to `CASE WHEN ... THEN ... ELSE ... END`.
- HANA `IN("SEGMENT",'CMX','MC')` was converted to `SEGMENT IN ('CMX', 'MC')`.
- The final SQL uses explicit column selection rather than `SELECT *` to preserve the logical model output structure.
- Generic intermediate join names were functionally renamed in the generated SQL:
  - Join_1 -> Topside_With_Store_Attributes
  - Join_2 -> Topside_With_Comp_Flag
  - Join_3 -> Topside_With_Retail_Calendar
  - Join_4 -> Topside_With_Profit_Center_Text
- Existing meaningful names were preserved:
  - TOPSIDE_ADJUSTMENTS
  - STORE_ATTRIBUTES
  - COMP_FLAG
  - RETAIL_CALENDAR
  - PROFIT_CENTER_TEXT
- External calculation views were represented as BigQuery table/view placeholders under `PROJECT.DATASET...` because actual BigQuery physical mappings were not provided.
- The input variables are represented as BigQuery query parameters:
  - `@IP_WEEK_ENDING_FROM`
  - `@IP_WEEK_ENDING_TO`
  - `@IP_VERSION_COMP_FLAG`
- NULL behavior of HANA scalar MAX with two arguments versus BigQuery GREATEST was not validated from the artifact and requires semantic validation.

- `PROJECT.DATASET.CV_BASE_TOPSIDE_ADJUSTMENTS_CAR`, `PROJECT.DATASET.CV_BASE_MD_SRPACT_S4`, `PROJECT.DATASET.CV_BASE_MD_COMPFL_S4`, `PROJECT.DATASET.CV_BASE_MD_RCALWEEK_S4`, and `PROJECT.DATASET.CV_BASE_MD_CEPCT_S4` are placeholders for the actual BigQuery mapped objects.
