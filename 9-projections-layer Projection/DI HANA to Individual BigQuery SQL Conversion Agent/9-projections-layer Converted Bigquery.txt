Overall Logic Summary:
This Calculation View (CV_COMP_FIN_FLASH) is a complex multi-source projection/join view that:

1. ACCEPTS TWO INPUT PARAMETERS:
   - IP_WEEK_ENDING_FROM and IP_WEEK_ENDING_TO, which are passed as PLACEHOLDERs to all referenced source Calculation Views to filter data to a specific fiscal week range.

2. READS FROM NINE SOURCE CALCULATION VIEWS:
   - CV_COMP_FIN_FLASH_STATIC    — Flash (actual front-store) financial data
   - CV_COMP_FIN_BUDGET_STATIC   — Financial budget data (referenced twice: once for main budget join, once for comp-level budget)
   - CV_COMP_SKF_BUDGET_STATIC   — Statistical key figure budget quantities
   - CV_COMP_FORECAST_MJE_STATIC — Forecast and manual journal entry data
   - CV_COMP_FIN_ACTUAL_STATIC   — Financial actual data (LY / prior year)
   - CV_COMP_SKF_ACTUAL_STATIC   — Statistical key figure actual quantities (LY)
   - CV_COMP_TOPSIDE_ADJUSTMENTS — Topside adjustment amounts (referenced twice: once for FS topside, once for RX topside)

3. JOINS all source views together (join types and join conditions are not fully exposed in the XML text — the join node column lists are present but join key columns and join types are not explicitly readable from the parsed XML text content).

4. APPLIES FILTERS:
   - SEGMENT filter: passes only rows where SEGMENT IS NULL or UPPER(SEGMENT) = 'CONVDRUG'
   - CAL_RX_BUDGET filter: passes only rows where CAL_RX_BUDGET = 0 or IS NULL (used to gate the ASP-based budget calculation path)
   - RX_BUDGET comp-level filter: passes only rows where BUDGET_COMP_FLAG IS NOT NULL AND (RX_BUDGET = 0 OR RX_BUDGET IS NULL)

5. COMPUTES INTERMEDIATE CALCULATED COLUMNS in a multi-step projection chain:
   Step A — Base sales calculations:
     CAL_FS_SALES = FS_SALESAMOUNT - REDUCTIONAMOUNT - EMP_REDUCTIONAMOUNT + CAL_FS_SALES_MJE + SBT
     CAL_RX_SALES = RX_SALESAMOUNT + CAL_RX_SALES_MJE
     CAL_SCRIPTS_90AS3 = CAL_SCRIPTS_90AS3_CAR + SKF_MJE_QTY
   Step B — Variance calculations (vs budget, forecast, LY):
     CAL_FS_BUDGET_VAR, CAL_FS_FCST_VAR, CAL_FS_LY_VAR
     CAL_RX_BUDGET_VAR, CAL_RX_FCST_VAR, CAL_RX_LY_VAR
     CAL_SCRIPTS_FCST_VAR, CAL_SCRIPTS_BUDGET_VAR, CAL_SCRIPTS_LY_VAR
     CAL_FS_SALES_BUDGET_VAR, CAL_FS_SALES_FCST_VAR, CAL_FS_SALES_LY_VAR
   Step C — Comp-store flags applied:
     CAL_COMP_FS_SALES, CAL_COMP_FS_SALESAMOUNT, CAL_COMP_RX_SALES, CAL_COMP_SCRIPTS, etc.
   Step D — ASP (Average Selling Price) chain:
     CAL_TOTAL_BUDGET_ASP → CAL_STORE_FLASH_ASP → CAL_TOTAL_FLASH_ASP → CAL_ASP_CHANGE_PERCT → CAL_ASP_ADJ_AMOUNT
   Step E — RX Budget derivation:
     CAL_RX_BUDGET: if RX_BUDGET is 0 or NULL, derive from SKF_BUDGET_QTY * CAL_ASP_ADJ_AMOUNT; otherwise use RX_BUDGET
   Step F — Comp-level RX Budget adjustment:
     For profit centers 0000502656 / 0000502657 with BUDGET_COMP_FLAG in ('0','1'):
       CAL_RX_BUDGET_FINAL = RX_BUDGET - CAL_RX_BUDGET_COMP_LEVEL
     Otherwise: CAL_RX_BUDGET_FINAL = CAL_RX_BUDGET
     CAL_COMP_RX_BUDGET = IF(BUDGET_COMP_FLAG='1', CAL_RX_BUDGET_FINAL, 0)

6. LOGICAL MODEL CALCULATED ATTRIBUTES (final output layer):
   - COMP_LABEL: text label derived from CAL_COMP_FLAG ('Comp' / 'Non-Comp' / '')
   - EMERG_MKT_IND_LABEL: 'Yes' / 'No' / '' from EMERG_MKT_IND
   - CAL_COMP_FLAG: max(coalesce(COMP_FLAG,'0'), coalesce(BUDGET_COMP_FLAG,'0'))
   - Date formatting: ZRWSTRTDATE_FMT, ZRWENDDATE_FMT, FS_OPEN_DAT_FMT, RX_OPEN_DAT_FMT using MM/DD/YYYY pattern
   - Timestamp formatting: FS_UPD_TIMESTAMP_FMT, RX_UPD_TIMESTAMP_FMT — constructed from integer timestamp columns using string slicing (LEFTSTR, MIDSTR, RIGHTSTR, STRING)

7. COMP-STORE VARIANCE MEASURES (final logical model):
   Twelve variance measures comparing comp-store actuals vs budget, forecast, and LY for FS, RX, 90AS3 scripts, and Corp FS.

Projected_Extended_Calculations AS (

    IF(FS_RX_FLAG = 'FS', CAL_FS_SALES - FIN_FCST_AMOUNT, 0)
      AS CAL_FS_SALES_FCST_VAR,
    IF(FS_RX_FLAG = 'FS', CAL_FS_SALES - FIN_LY_AMOUNT, 0)

      AS CAL_ASP_CHANGE_PERCT
  FROM Projected_Extended_Calculations
),

Projected_ASP_Adj AS (
  SELECT
    *,
    IF(CAL_ASP_CHANGE_PERCT = -1, 0,
       ROUND(CAL_STORE_FLASH_ASP / (1 + CAL_ASP_CHANGE_PERCT), 2))
      AS CAL_ASP_ADJ_AMOUNT
  FROM Projected_ASP_Calculations

         RX_BUDGET - CAL_RX_BUDGET_COMP_LEVEL,  -- UNRESOLVED

CONVERSION_NOTES:

1. ARTIFACT TYPE:
   The input is a SAP HANA Calculation View XML (9-projections-layer.xml). The view
   is identified as CV_COMP_FIN_FLASH within the CVS_FRIP.Composite.FI package.

2. dataCategory / outputViewType:
   Neither dataCategory="CUBE" nor outputViewType="Aggregation" was confirmed in the
   parsed XML root element. The view is treated as a row-level projection view.
   No mandatory GROUP BY + aggregation is applied at the final SELECT level.

3. INPUT PARAMETERS (IP_WEEK_ENDING_FROM, IP_WEEK_ENDING_TO):
   In HANA, these are passed to source Calculation Views via PLACEHOLDER syntax:
     PLACEHOLDER."(IP_WEEK_ENDING_FROM)" => :IP_WEEK_ENDING_FROM
   In BigQuery, these are declared as scripting variables (DECLARE/SET).
   Their actual data types are UNRESOLVED. They are used to filter the source views
   to a specific fiscal week range. The actual filter application inside each source
   view is UNRESOLVED because the source view definitions are not included.

4. SFN_PRIOR_FISCAL_WEEK (CVS_FRIP.Composite.Master::SFN_PRIOR_FISCAL_WEEK):
   This is a HANA scalar function referenced in filter expressions on source views.
   Its definition is not available in the input XML. It is marked as UNRESOLVED.
   The filter conditions that use it cannot be converted without the function definition.

5. SOURCE CALCULATION VIEWS (all UNRESOLVED):
   All nine source Calculation Views are external dependencies not defined in this XML.
   They are referenced with placeholder BigQuery paths:
     `PROJECT.DATASET.<view_name>`
   The actual BigQuery project, dataset, and object names must be provided.

6. JOIN TYPES AND JOIN CONDITIONS (UNRESOLVED):
   The XML join nodes list the columns projected from each side of each join, but the
   actual join type (INNER/LEFT/RIGHT/FULL) and the join key columns are not fully
   exposed in the parsed XML text content. All joins are represented as LEFT JOINs
   with TRUE placeholder conditions. These must be validated and corrected.

7. CAL_TOTAL_BUDGET_ASP — CIRCULAR DEPENDENCY NOTE:
   In the HANA XML, CAL_TOTAL_BUDGET_ASP is defined as:
     IF(SKF_BUDGET_QTY=0, 0, ROUND(CAL_RX_BUDGET/SKF_BUDGET_QTY, 2))
   However, CAL_RX_BUDGET itself depends on CAL_ASP_ADJ_AMOUNT, which depends on
   CAL_TOTAL_BUDGET_ASP. This creates a circular dependency in the formula chain.
   In the HANA model, this is resolved by the node execution order — CAL_RX_BUDGET
   is computed in a later node that references a prior-computed CAL_RX_BUDGET value
   (from the raw RX_BUDGET column), not the derived one. In the BigQuery conversion,
   the CAL_TOTAL_BUDGET_ASP step uses RX_BUDGET (the raw column) as a proxy for the
   initial budget ASP calculation. This must be validated against the actual HANA
   node execution order.

8. CAL_RX_BUDGET_COMP_LEVEL (UNRESOLVED):
   This column is referenced in the formula:
