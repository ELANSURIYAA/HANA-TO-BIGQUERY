SOURCE_LOGIC:

ARTIFACT TYPE: SAP HANA Calculation View XML

ROOT ELEMENT ATTRIBUTES:
  - dataCategory: CUBE
  - outputViewType: Aggregation

AGGREGATION REQUIREMENT:
  Because dataCategory="CUBE" and outputViewType="Aggregation", the final output
  of this Calculation View is AGGREGATED. The final SELECT must apply SUM() (or
  the declared aggregation function) to every measure column and must GROUP BY
  every non-measure attribute column. This is a mandatory correctness requirement.

OVERALL FLOW SUMMARY:
  The view combines financial flash, budget, SKF (statistical key figures),
  forecast, actual, and topside adjustment data from multiple source Calculation
  Views. It applies week-ending range filters via input parameters
  IP_WEEK_ENDING_FROM and IP_WEEK_ENDING_TO, computes a series of calculated
  sales, budget, variance, and ASP (Average Sales Price) columns through a
  chain of projection nodes, and then aggregates the results in the logical model.

DETAILED NODE-BY-NODE LOGIC:

STEP 1 — Projected_Flash_And_Actuals
  Sources: CV_COMP_FIN_FLASH_STATIC, CV_COMP_FIN_BUDGET_STATIC,
           CV_COMP_SKF_BUDGET_STATIC, CV_COMP_FORECAST_MJE_STATIC,
           CV_COMP_FIN_ACTUAL_STATIC, CV_COMP_SKF_ACTUAL_STATIC,
           CV_COMP_TOPSIDE_ADJUSTMENTS (first reference)
  Filter: WEEK_ENDING BETWEEN #IP_WEEK_ENDING_FROM AND #IP_WEEK_ENDING_TO
          (applied to multiple source views via placeholder parameters)
  Calculated columns produced:
    CAL_FS_SALES, CAL_RX_SALES, CAL_SCRIPTS_90AS3,
    CAL_FS_VS_BUDGET, CAL_FS_VS_FCST, CAL_FS_VS_LY,
    CAL_RX_VS_BUDGET, CAL_RX_VS_FCST, CAL_RX_VS_LY,
    CAL_SCRIPTS_VS_FCST, CAL_SCRIPTS_VS_BDG, CAL_SCRIPTS_VS_LY,
    CAL_CORPFS_VS_BUDGET, CAL_CORPFS_VS_FCST, CAL_CORPFS_VS_LY,
    CAL_COMP_BUDGET, CAL_COMP_FS_SALES, CAL_COMP_FS_SALESAMT,

    CAL_COMP_FCST, CAL_COMP_SKF_FCST, CAL_COMP_LY, CAL_COMP_SKF_LY

STEP 2 — Projected_ASP_Calculations
  Source: Projected_Flash_And_Actuals
  Filter: (SEGMENT IS NULL) OR UPPER(SEGMENT) = 'CONVDRUG'
  Calculated columns produced:
    CAL_TOTAL_BUDGET_ASP  = IF(SKF_BUDGET_QTY=0, 0, ROUND(CAL_RX_BUDGET/SKF_BUDGET_QTY,2))
    CAL_TOTAL_FLASH_ASP   = IF(CAL_SCRIPTS_90AS3=0, 0, ROUND(CAL_RX_SALES/CAL_SCRIPTS_90AS3,2))
    CAL_ASP_CHANGE_PERCT  = IF(CAL_TOTAL_BUDGET_ASP=0, 0,
                               ROUND((CAL_TOTAL_FLASH_ASP/CAL_TOTAL_BUDGET_ASP)-1, 4))

STEP 3 — Projected_Store_Flash_ASP
  Source: Projected_Flash_And_Actuals
  Filter: (CAL_RX_BUDGET = 0) OR ISNULL(CAL_RX_BUDGET)
  Calculated column produced:
    CAL_STORE_FLASH_ASP = IF(CAL_SCRIPTS_90AS3=0, 0,
                             ROUND(CAL_RX_SALES/CAL_SCRIPTS_90AS3, 2))

STEP 4 — Projected_ASP_Adj_Amount
  Source: Projected_Store_Flash_ASP joined with Projected_ASP_Calculations
          (join type and join condition not explicitly visible in parsed XML;
           treated as UNRESOLVED — see UNRESOLVED_ITEMS)
  Calculated column produced:
    CAL_ASP_ADJ_AMOUNT = IF(CAL_ASP_CHANGE_PERCT=-1, 0,
                            ROUND(CAL_STORE_FLASH_ASP/(1+CAL_ASP_CHANGE_PERCT), 2))

STEP 5 — Projected_RX_Budget_Final
  Source: Projected_Flash_And_Actuals joined with Projected_ASP_Adj_Amount
          (join type and join condition not explicitly visible in parsed XML;
           treated as UNRESOLVED — see UNRESOLVED_ITEMS)
  Calculated column produced:
    CAL_RX_BUDGET_FINAL = IF(RX_BUDGET=0 OR ISNULL(RX_BUDGET),
                             ROUND(SKF_BUDGET_QTY * CAL_ASP_ADJ_AMOUNT, 2),
                             RX_BUDGET)

STEP 6 — Projected_Comp_Level_Budget
  Source: CV_COMP_FIN_BUDGET_STATIC (second reference) and
          CV_COMP_TOPSIDE_ADJUSTMENTS (second reference)
  Filter: (NOT ISNULL(BUDGET_COMP_FLAG)) AND (RX_BUDGET=0 OR ISNULL(RX_BUDGET))
  Calculated column produced:
    PRCTR (override) = IF(BUDGET_COMP_FLAG='1', '0000502656', '0000502657')

STEP 7 — Projected_Final_RX_Budget_Adjustment
  Source: Projected_RX_Budget_Final joined with Projected_Comp_Level_Budget
          (join type and join condition not explicitly visible in parsed XML;
           treated as UNRESOLVED — see UNRESOLVED_ITEMS)
  Calculated columns produced:
    CAL_RX_BUDGET_FINAL = IF(IN(PRCTR,'0000502656','0000502657')
                             AND IN(BUDGET_COMP_FLAG,'0','1'),
                             RX_BUDGET - CAL_RX_BUDGET_COMP_LEVEL,
                             CAL_RX_BUDGET)
    CAL_COMP_RX_BUDGET  = IF(BUDGET_COMP_FLAG='1', CAL_RX_BUDGET_FINAL, 0)

CONVERSION_NOTES:

1. ARTIFACT TYPE AND AGGREGATION:
   The root Calculation View element has dataCategory="CUBE" and
   outputViewType="Aggregation". Per the conversion rules, the final SELECT
   applies SUM() to all measure columns and includes a GROUP BY clause on all
   non-measure attribute columns. This is mandatory for correctness.

2. GENERIC CTE RENAMING:
   The XML contained multiple generic projection node identifiers (PROJECTION_1
   through PROJECTION_N equivalent). These have been renamed to functional names
   based on the actual transformation logic found in the XML:
   - Projected_Flash_And_Actuals   (main data combination and variance calc node)
   - Projected_ASP_Calculations    (ASP computation with SEGMENT filter)
   - Projected_Store_Flash_ASP     (store flash ASP with CAL_RX_BUDGET=0 filter)
   - Projected_ASP_Adj_Amount      (ASP adjustment amount computation)
   - Projected_RX_Budget_Final     (final RX budget with ASP adjustment)
   - Projected_Comp_Level_Budget   (comp-level budget with PRCTR override)
   - Projected_Final_RX_Budget_Adjustment (final RX budget adjustment and comp flag)
   No existing meaningful names were renamed.

3. INPUT PARAMETERS (IP_WEEK_ENDING_FROM, IP_WEEK_ENDING_TO):
   These are declared as BigQuery DECLARE variables. Their default values in
   HANA are computed by CVS_FRIP.Composite.Master::SFN_PRIOR_FISCAL_WEEK,
   which is an external scalar function not defined in the source XML. Default
   values are set to NULL as placeholders. The actual BigQuery equivalent
   (a scalar expression or literal) must be supplied by the implementer.

4. HANA IF() → BigQuery IF():
   HANA IF() and BigQuery IF() have the same three-argument semantics. No
   conversion change required.

5. HANA ISNULL() → BigQuery IS NULL:
   HANA ISNULL(x) is equivalent to BigQuery x IS NULL. Converted accordingly.
   In calculated column formulas, ISNULL() in conditions has been converted to
   IS NULL.

6. HANA IN() → BigQuery IN():
   HANA IN("PRCTR",'0000502656','0000502657') is equivalent to BigQuery
   PRCTR IN ('0000502656','0000502657'). Converted accordingly.

7. HANA ROUND() → BigQuery ROUND():
   Both functions take (value, decimal_places) and have equivalent semantics
   for standard numeric rounding. Converted directly.

8. HANA UPPER() → BigQuery UPPER():
   Equivalent. Converted directly.

9. HANA CASE() (decode-style) → BigQuery CASE WHEN:
   HANA: case("CAL_COMP_FLAG",'1','Comp','0','Non-Comp','')
   BigQuery: CASE CAL_COMP_FLAG WHEN '1' THEN 'Comp' WHEN '0' THEN 'Non-Comp'
             ELSE '' END
   The trailing empty string in HANA's case() is the default/else value.

10. HANA scalar MAX(a, b) → BigQuery GREATEST(a, b):
    HANA: max(coalesce("COMP_FLAG",'0'), coalesce("BUDGET_COMP_FLAG",'0'))
    In this context, max() is a two-argument scalar function returning the
    greater of two values, NOT an aggregate MAX. BigQuery GREATEST() is the
    correct equivalent. NULL behavior: GREATEST() in BigQuery returns NULL if
    any argument is NULL; however, COALESCE ensures neither argument is NULL
    here, so behavior is equivalent.

11. HANA COALESCE() → BigQuery COALESCE():
    Equivalent. Converted directly.

12. HANA format(date(...), 'MM/DD/YYYY') → BigQuery FORMAT_DATE('%m/%d/%Y', ...):
    HANA FORMAT with 'MM/DD/YYYY' maps to BigQuery FORMAT_DATE with '%m/%d/%Y'.
    The datatype of ZRWSTRTDATE_SAP, ZRWENDDATE_SAP, FS_OPEN_DAT_SAP, and
    RX_OPEN_DAT_SAP is UNRESOLVED. A CAST to DATE is included as a placeholder.
    If these columns are already DATE type, remove the CAST. If they are strings
    in YYYYMMDD format, use PARSE_DATE('%Y%m%d', col) instead.

13. HANA timestamp string formatting (midstr/leftstr/rightstr/STRING):
    HANA formula:
      midstr(STRING("FS_UPD_TIMESTAMP_SAP"),5,2) + '/' + ...
    This treats the timestamp as a 14-digit integer (YYYYMMDDHHMMSS), converts
    it to a string, and extracts substrings to form MM/DD/YYYY HH:MM:SS.
    BigQuery equivalent:
      SUBSTR(CAST(col AS STRING), pos, len) for midstr
      RIGHT(CAST(col AS STRING), len) for rightstr
      String concatenation uses || operator in BigQuery Standard SQL.
    HANA midstr(str, start, length) is 1-based. BigQuery SUBSTR(str, pos, len)
    is also 1-based. Positions are preserved exactly.
    NOTE: The datatype of FS_UPD_TIMESTAMP_SAP and RX_UPD_TIMESTAMP_SAP is
    UNRESOLVED. A CAST to STRING is included. If the column is already STRING,
    remove the CAST.

14. HANA leftstr(str, n) → BigQuery LEFT(str, n):
    Equivalent. Not used in the final SELECT directly but noted for completeness.
    In the timestamp formula, leftstr(STRING(col), 4) is converted to
    SUBSTR(CAST(col AS STRING), 1, 4) for consistency with the midstr pattern.

15. HANA rightstr(str, n) → BigQuery RIGHT(str, n):
    Equivalent. Used in the timestamp formula as RIGHT(CAST(col AS STRING), 2).

16. HANA STRING() → BigQuery CAST(col AS STRING):
    HANA STRING() converts a value to its string representation. BigQuery
    CAST(col AS STRING) is the equivalent.

17. HANA BETWEEN for parameter filter:
    WEEK_ENDING BETWEEN #IP_WEEK_ENDING_FROM AND #IP_WEEK_ENDING_TO
    Converted to BigQuery:
    WEEK_ENDING BETWEEN IP_WEEK_ENDING_FROM AND IP_WEEK_ENDING_TO
    The datatype of WEEK_ENDING and the parameters is UNRESOLVED. If WEEK_ENDING
    is a DATE, the parameters should also be DATE type. Adjust DECLARE
    statements accordingly.

18. HANA ISNULL() in filter conditions:
    HANA: (isNull("SEGMENT")) or UPPER("SEGMENT")='CONVDRUG'
    BigQuery: SEGMENT IS NULL OR UPPER(SEGMENT) = 'CONVDRUG'
    Converted correctly.

19. HANA NOT ISNULL() in filter conditions:
    HANA: (not isNull("BUDGET_COMP_FLAG"))
    BigQuery: BUDGET_COMP_FLAG IS NOT NULL
    Converted correctly.

20. SOURCE VIEW COMBINATION METHOD (UNRESOLVED):
    The XML lists multiple source Calculation Views as dataSources but does not
    define the join or union structure between them in the parsed content. The

21. JOIN CONDITIONS FOR INTERMEDIATE NODES (UNRESOLVED):
    The join conditions between Projected_Store_Flash_ASP and
    Projected_ASP_Calculations (Step 4), between Projected_Flash_And_Actuals
    and Projected_ASP_Adj_Amount (Step 5), and between Projected_RX_Budget_Final

22. SBT COLUMN:

24. LOGICAL MODEL CALCULATED MEASURES POST-AGGREGATION:
    Per HANA CUBE/Aggregation rules, calculated measures that reference other
    measures (e.g., CAL_COMP_FS_VS_BUDGET = CAL_COMP_FS_SALESAMOUNT -

    row-by-row. In the BigQuery SQL, these are expressed as
